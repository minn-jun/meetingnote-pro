## D1. 퍼블리싱 HTML 과 디자인 규칙이 어긋날 때

**결정: 화면 구조와 색은 publish 를 따르고, 규칙을 어긴 곳만 theme.js 규칙에 맞춘다.**

| 어긋난 곳 | 처리 |
|---|---|
| `detail.html` 수정·삭제·취소 버튼 `h-10`, `team.html` 이름 저장 `h-9`, `todos.html` 담당자 필터 select `h-10` | 모두 `h-11`. 버튼은 `UI.btnPrimary` · `UI.btnGhost` · `UI.btnDanger` 를 쓴다 |
| `team.html` 「이름 저장」 `bg-blue-dot` (색을 면으로 깔음) | `UI.btnPrimary` 로 바꾼다 |
| 화면이 `window.UI` 를 쓰지 않고 같은 클래스 문자열을 직접 적음 | 구현은 `window.UI` 이름만 쓴다. 화면에 반복되는 조합(헤더 nav 항목, 탭, 카드 안 작은 배지, 카드 안 select, 칸 고르기 버튼 등)은 theme.js 에 이름을 먼저 등록한 뒤 쓴다 |
| 화면 배지 `px-2 py-0.5 text-[10px]` 와 `UI.badge`(`px-2.5 py-1 text-[11px]`) 가 다름 | 둘 다 둔다. 화면 값은 카드 안 작은 배지로 theme.js 에 새 이름으로 등록하고, `UI.badge` 는 지금처럼 owner 배지 등에 쓴다 |
| 변형 버튼 (빨간 글자 고스트 「삭제」 등) | 화면에서 `UI.btnGhost + LABEL.red` 로 조합하지 않는다. theme.js 에 변형 이름으로 등록한다 |
| `meetings.html` 진행률 막대 `style="width:0%"`, 칸반 끌기 사본의 `style.left/top` | 마크업의 `style` 속성은 금지. 진행률 · 좌표처럼 실행 중에 바뀌는 값만 JS 로 `element.style` 을 설정하는 것을 허용한다 |

화면 문구:

- 라벨 · placeholder · 버튼 글자 · 빈 상태 문구는 publish 를 따른다
- 오류 · 알림 메시지는 스토리보드의 존댓말 문장을 쓴다 (예: 「이메일 또는 비밀번호가 올바르지 않습니다」)
- 구현에서 빼는 것: STATE 바(`window.stateBar`), 「퍼블리싱 확인용」 note 줄, 토스트 본문의 API 경로 · 상태 코드

## D2. 받아쓰기 공급자와 모델

**결정: Google Gemini 하나로 한다. 받아쓰기 · 3항목 구분이 같은 키(`STT_API_KEY`)와 같은 모델을 쓴다.** (2026-10-06 사용자 지시로 OpenAI 에서 바꿈)

- 모델은 `gemini-3.8-flash` 다. 정식(Stable) 버전이고 오디오 입력과 구조화 출력(JSON)을 지원하는 것을 공식 문서에서 확인했다. 한 모델이 받아쓰기와 구분을 모두 하므로 정의서의 「같은 모델에 다시 넣어」와 맞다
- SDK 는 `google-genai`. 키는 Google AI Studio 에서 발급한다
- 인라인 요청은 통째로 20MB 까지라, 12MB 를 넘는 녹취는 Files API 로 올린 뒤 받아쓴다
- 3항목 구분은 JSON 스키마 구조화 출력으로 요약 · 결정사항 · 할 일 셋을 받는다
- 모델 이름은 코드에 박지 않고 `.env` 의 `STT_MODEL` · `SUMMARY_MODEL` 로 바꿀 수 있게 한다
- 처음 정한 안: OpenAI (`gpt-4o-transcribe` + 대화 모델). 업로드 조건이 OpenAI 제한과 같다는 이유였다
- 테스트는 공급자 호출을 가짜로 바꿔 끼워 키 없이 돈다
- 위험: 25MB 녹취(약 25분)는 받아쓰기 60초 제약을 넘을 수 있다. 1회차에서는 재기만 하고 제약은 그대로 둔다

## D3. 배포 환경의 업로드 용량

Vercel 함수는 요청 본문을 4.5MB 까지만 받는다. 25MB 업로드는 배포 환경에서 함수에 닿기 전에 막힌다.

**결정: 상한을 환경변수 `MAX_UPLOAD_MB` 로 둔다. 로컬은 25, 배포는 4. 넘으면 같은 `413 PAYLOAD_TOO_LARGE` 를 돌려준다.**

- 화면 안내 문구의 숫자도 서버 설정값을 따른다
- Vercel Blob 으로 직접 올리는 방식(25MB 그대로)은 다음 회차 후보로 남긴다

## D4. 기한 지남 판정

`due_text` 는 자유 글자라 화면이 「지난 날짜」를 판정할 근거가 없다.

**결정: 날짜를 알 수 있으면 `YYYY-MM-DD` 로 저장하고, 화면은 이 형식만 판정한다.**

- 3항목 구분 때 「다음 주 금요일」 같은 상대 표현은 회의 시각(`met_at`)을 기준으로 `YYYY-MM-DD` 로 바꿔 저장한다. 날짜를 정할 수 없으면 원래 글자를 두고, 기한이 없으면 「미정」으로 둔다
- 화면 판정: `due_text` 가 `YYYY-MM-DD` 로 시작하고 오늘(현지 날짜)보다 앞이며 상태가 DONE 이 아니면 기한 지남(붉은 띠)이다. 그 밖의 글자는 기한 지남으로 보지 않는다
- 서버는 여전히 비교하지 않는다 (정의서 7-2 그대로)

## D5. 사람당 팀 수

**결정: 한 사람은 팀 하나에만 속한다.**

- `GET /api/teams` 는 0건 또는 1건을 돌려준다. 화면은 첫 건을 현재 팀으로 쓴다
- 이미 팀이 있는 사람이 팀을 만들거나 합류하면 `400 VALIDATION_ERROR` 를 돌려준다 (오류 코드 14종 밖의 코드를 새로 만들지 않는다)
- `/api/auth/me` 의 `role` 은 그 한 팀에서의 역할이다. 팀이 없으면 `null`

## D6. 응답 규칙에 빠진 것

- **회의록 단건 응답**: 목록 필드 + `body` · `decisions` · `author_id` 에 `todos` 배열을 더한다. 배열 항목은 할 일 목록 응답과 같은 형식이다. 담당자 select 의 선택지는 멤버 목록 API 로 받는다 (D8 의 예외 참고)
- **팀 생성**: 만든 사람은 owner 멤버십을 받는다. 활동 기록에는 남기지 않는다. `member_join` 은 초대코드 합류에만 쓴다 (kind 5종 그대로)

**결정: `add-mvp-core` change 하나에 1회차 기능 6종 + 배포를 담는다** (정의서 10장대로).

- 로테이션 2 · 3회차에 무엇을 할지는 문서에 없다. 미정으로 둔다

## D8. 화면과 API 의 연결은 스토리보드 매핑표(I-01)를 따른다

사용자 지시 (2026-10-06): 「스토리보드 매핑표대로 간다」.

| 화면 | 부르는 API |
|---|---|
| login.html | auth/signup · auth/login · teams/join |
| meetings.html | teams/{id}/meetings (POST·GET) · upload · auth/me · auth/logout |
| detail.html | meetings/{id} (GET·PUT·DELETE) · todos/{id} (PUT) · meetings/{id}/comments (POST·GET) · comments/{id} (DELETE) |
| todos.html | teams/{id}/todos · todos/{id} (PUT·DELETE) · me/todos |
| team.html | teams (POST·GET) · teams/{id} (PUT) · teams/join · teams/{id}/members · teams/{id}/code · teams/{id}/activities |
| profile.html | auth/me (GET·PUT) · me/todos · me/activities |

매핑표와 퍼블리싱이 어긋나는 곳 (잠정 처리):

- **담당자 선택지**: detail.html 의 담당자 select 와 todos.html 의 담당자 배지 · 필터는 팀 멤버 목록이 있어야 그릴 수 있는데, 매핑표에는 두 화면에 `teams/{id}/members` 가 없다. 응답 형식(정의서 7-1)을 바꾸지 않으려고 **두 화면에서 `GET /api/teams/{id}/members` 를 추가로 부르는 것을 예외로 허용**한다
- **로그아웃 버튼**: 퍼블리싱은 profile.html 에 로그아웃 버튼이 있고, 매핑표는 `auth/logout` 을 meetings.html 에 둔다. 확정 디자인인 profile.html 의 버튼을 살려 **profile.html 에서도 `POST /api/auth/logout` 을 부른다**. meetings.html 은 매핑표대로 진입 때 `auth/me` 로 로그인 · 팀 확인을 하고, 토큰이 만료되면 로그아웃 처리한다

## D9. Swagger UI

사용자 지시 (2026-10-06): 「Swagger UI 켜서 화면에서 API 테스트할 수 있게」.

- FastAPI 기본 문서 화면을 켠다. `/docs` (Swagger UI), `/openapi.json`
- 인증은 Bearer 보안 스키마로 등록해 Swagger 의 Authorize 버튼에 로그인 토큰을 넣고 보호된 API 를 바로 부를 수 있게 한다
- `POST /api/upload` 는 multipart 파일 입력으로 등록해 Swagger 에서 녹취 파일을 골라 올릴 수 있게 한다
- 모든 API 에 묶음 태그(Auth · Team · Meeting · Todo · Comment · Activity)와 요청 · 응답 스키마를 단다
- 정적 파일(frontend)은 API 라우트 뒤에 붙여 `/docs` 를 가리지 않게 한다
- 배포 환경에서도 켜 둔다 (끄려면 환경변수로 끌 수 있게만 해 둔다)

사용자 지시 (2026-10-06): 「개발 끝나면 pytest 짜서 돌리고 결과 보고」.

## D12. 오류 코드 보충과 권한 세부

propose 단계에서 spec 을 쓰며 정했다.

- **`502 UPSTREAM_ERROR` 를 하나 더한다.** 받아쓰기 · 3항목 구분 공급자가 실패했을 때 쓸 코드가 14종 안에 없다. D5 의 「새 코드를 만들지 않는다」 예외는 이것 하나뿐이다. 구분이 실패하면 회의록을 저장하지 않는다 (입력칸은 그대로 남아 다시 누를 수 있다)
- **토큰이 없거나 위조된 경우도 `401 TOKEN_EXPIRED`** 로 돌려준다. 화면 처리가 만료와 같다 (토큰 지우고 로그인으로)
- **가입 · 로그인 응답에 `team_id` 를 싣는다.** login.html 이 매핑표상 `auth/me` 를 부르지 않으므로 이동할 화면(meetings / team)을 이 값으로 정한다
- **회의록 수정도 쓴 사람과 owner 만** 한다 (정의서는 삭제만 적었다). 그 밖은 `403 FORBIDDEN`
- **할 일 상태 · 담당자 · 기한 변경은 팀 멤버 누구나** 한다. 삭제만 owner

## D13. 칸반 기한 배지

- 기한 배지를 누르면 미정 → 오늘 → 내일 → 이번 주 금요일 → 다음 주 금요일 → 미정 순으로 바뀐다. 미정 외에는 `YYYY-MM-DD` 로 저장한다 (D4 와 맞춤)
- publish 의 순환 목록(「이번 주 안」 · 「어제」 · 「지난 주」 등 글자)은 기한 지남을 판정할 수 없어 바꾼다

## D15. 구현하며 정한 것

apply 단계에서 정했다.

- **가입 · 로그인 응답에 `team_name` 도 싣는다.** 매핑표상 meetings.html 등은 팀 조회 API 를 부르지 않는데 헤더에 팀 이름을 보여야 한다. 화면은 로그인 · 팀 생성 · 합류 응답의 팀 id · 이름을 localStorage 에 두고 쓴다
- **`/config.js` 를 둔다.** D3 의 「화면 안내 문구의 숫자도 서버 설정값을 따른다」를 지키려면 화면이 업로드 상한을 알아야 한다. API 26개를 늘리지 않으려고 `/api/` 가 아닌 화면용 스크립트로 `MAX_UPLOAD_MB` 한 값만 내려 준다. Swagger 에는 나오지 않는다
- **내 id 와 역할은 화면이 구한다.** detail.html · todos.html 은 매핑표상 `auth/me` 를 부르지 않는다. 내 id 는 토큰(JWT)의 `sub` 에서 읽고, 역할은 D8 예외로 부르는 멤버 목록에서 찾는다. 수정 · 삭제 버튼을 보일지 정하는 데만 쓰고, 권한 판정은 서버가 한다
- **상세 화면의 수정 모드**: publish 는 제목만 고치는 모습이지만 spec 은 제목 · 시각 · 참석자 · 본문을 고친다. 수정 모드에서 시각 · 참석자 입력칸과 본문 textarea 를 `UI.input` · `UI.textarea` 로 띄운다
- **상세 화면의 상태 변경**: publish 의 상태 배지는 표시뿐이라 스토리보드 D-04(상태 변경)를 할 수단이 없다. 배지를 누르면 대기 → 진행 → 완료 → 대기 로 바뀌게 한다
- **녹취 파일 고르기**: 끌어다 놓기 칸을 눌러도 파일 선택 창이 뜬다 (휴대폰에서는 끌어다 놓을 수 없다)
- **bcrypt 비용을 10 으로 한다.** 라이브러리 기본값 12 는 개발 PC 에서 해시 한 번에 250ms 쯤 걸려, 정의서의 「회원가입 · 로그인 250ms 이내」를 넘는다 (성능 테스트에서 로그인 250ms 로 실패). 10 은 약 60~70ms 이고 흔히 권장되는 최소값이다
